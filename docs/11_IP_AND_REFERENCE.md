# Referências e direitos de propriedade intelectual

O usuário esclareceu que o jogo enviado como exemplo foi criado por um colega. Isso **não significa** que o código-fonte, modelos, texturas, UI, sons, personagens ou mapas tenham sido licenciados para nosso uso comercial. Não incorporar nada disso por padrão.

Pode-se estudar princípios gerais de mecânicas e inspiração de gênero; não copiar expressão protegida. O protótipo de batatas citado no relatório não deve ser assumido como propriedade do projeto sem confirmação de autoria e direitos.

## Regra de migração
- Separar ideia genérica (loop colher/vender) de implementação específica do colega.
- Se houve código criado independentemente pelo usuário, identificar arquivos de autoria própria e limpar referências.
- Reimplementar em Luau original, a partir de GDD nosso.
- Registrar a origem de cada asset e biblioteca; modelos de Toolbox sempre passam auditoria.
- Salvar autorizações explícitas caso venham a existir, mas não depender delas para o MVP.
